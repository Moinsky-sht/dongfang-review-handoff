# 规则归纳任务说明（所有规则归纳子任务共用）

## 背景
《东方学刊》编辑部从 2024 年秋季刊起改用 Word 修订模式做一审：修改用修订痕迹完成，与作者的沟通写进批注，注释里无法加批注的地方用方头括号【】加说明。
现有 598 份一审稿件的结构化提取结果，共 8687 条批注（去重后 2316 种表述）、27190 处段落级修订对照。

## 你的输入素材在哪
`data/comments/chunks/<主题>/` 目录下是**已按主题筛选并切好片**的批注材料，每个片段约 8KB。
- 每个片段由若干"块"组成，块格式为：
  ```
  ### <主题> | <文件名> | 锚点：<被批注的正文片段>
  <批注正文>
  ```
- `锚点：` 后面是批注所依附的稿件正文，理解批注语境就靠它。

请**读完全部片段**（数量不多，逐个用 read 工具读；片段多时可以并行读多个文件）。

## 你要产出什么
一个 JSON 文件（路径由你的任务指定），结构：

```json
{
  "meta": {
    "scope": "本次归纳的主题范围",
    "materialRead": "读了哪些片段，共多少条批注",
    "generatedAt": "ISO 日期"
  },
  "rules": [
    {
      "id": "PREFIX-001",
      "category": "子类，例如 搭配不当 / 标题层级 / 脚注著录",
      "title": "一句话规则名",
      "severity": "高|中|低",
      "rule": "完整、无歧义、可直接作为校对依据的规则陈述（2-4 句）",
      "detect": {
        "type": "regex|structure|list|model|manual",
        "patterns": ["JS 正则字符串，可留空数组"],
        "lexicon": ["需要重点检查的词/短语清单"],
        "method": "如何在 docx 结构或正文文本上判断，写具体步骤"
      },
      "autoFixable": false,
      "evidence": [
        {"file": "文件名（可截断）", "comment": "批注原文（必须与素材一字不差）"}
      ],
      "occurrences": 12
    }
  ],
  "lexicon": {}
}
```

## 硬性要求
1. **evidence.comment 必须是素材里真实存在的批注原文**，一字不改，不得编造。每条规则至少 1 条、尽量 2-3 条证据。
2. `occurrences` 是你观察到的该类问题在素材中的大致次数（同类归并后计数）。
3. 规则必须**具体到可执行**。反例："标点要规范"。正例："中文语境下并列词语之间用顿号；「即」字前不用顿号；英文缩写与中文之间不加顿号。"
4. 正则必须能在中文文本上安全运行（JS 语法），**不要写会大面积误报的贪婪正则**。能用词表精确命中的就写 lexicon，不要硬写正则。
5. `lexicon` 尽量充实（能列 100 条以上就列），这是后续词表扫描的依据。
6. 规则按出现频次从高到低排列。
7. 只写 JSON，不要写 markdown 代码块包裹，不要写额外说明文字到该文件里。

## 语气与判断标准
以"应该怎样写才对"来陈述规则，而不是复述批注。批注里大量是责编在向作者提问（如"请核对""妥否""是否要改"），你要把提问背后的**编辑标准**提炼出来。
